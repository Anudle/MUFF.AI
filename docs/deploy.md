# Deploying the MCP server to Lambda (MUFF-39)

One command, idempotent:

```
npm run deploy      # bundle → zip → secret → IAM role → Lambda → Function URL
npm run verify:remote
```

## Architecture

```
MCP client (agent / digest pipeline / Inspector)
      │  Streamable HTTP (POST JSON-RPC, Bearer token)
      ▼
API Gateway HTTP API  ($default route → Lambda proxy, payload v2.0)
      ▼
muff-mcp-server      (nodejs22.x, 512 MB, 30 s timeout)
  src/mcp/lambda.ts   — proxy event (v2.0) ⇄ web Request/Response
  src/mcp/http.ts     — bearer check + stateless Streamable HTTP transport
  src/mcp/build-server.ts — the five Yahoo tools (shared with stdio)
      │
      ├── Secrets Manager: muff/yahoo-tokens  (read + write-back on refresh)
      └── Yahoo Fantasy API
```

The same `buildServer()` powers both transports; `npm run mcp` (stdio) and the
deployed endpoint expose identical tools. `npm run mcp:http` runs the exact
Lambda code path locally on port 3939.

## The CCA-F concepts in play

**MCP transports.** stdio is for a server the client launches as a child
process; Streamable HTTP is for a server that lives elsewhere. Streamable HTTP
is one endpoint accepting POSTed JSON-RPC messages, with optional SSE for
streaming and optional sessions for stateful servers.

**Stateless mode is what makes Lambda viable.** Lambda containers appear and
vanish, and two requests in one MCP "conversation" can land on different
containers — so the server can't hold sessions. We disable them
(`sessionIdGenerator: undefined`) and build a fresh `McpServer` per request.
That works because our tools are pure reads: nothing depends on per-session
state. A stateful server (sampling, subscriptions, long streams) would need
sticky infrastructure (Fargate/ECS) instead — matching the transport mode to
the compute model is the design decision here.

**JSON response mode.** `enableJsonResponse: true` returns one JSON body per
POST instead of opening an SSE stream. The API Gateway proxy integration
buffers responses anyway and no tool streams partial results, so SSE would
add moving parts for nothing. GET (SSE resume) and DELETE (session teardown)
return 405 — with no sessions there's nothing to resume or tear down; the
spec allows exactly this.

**Auth layering.** AWS-layer auth options (IAM/SigV4) require request
signing, which MCP clients don't speak — so the AWS front door is public and
the app layer enforces a static bearer token (`MCP_AUTH_TOKEN`, generated by
the deploy script into `.env`), failing **closed** if the var is missing in
Lambda. The MCP spec's full remote-auth story is OAuth; for a single-user
personal endpoint, a bearer token is the proportionate rung on that ladder.

**Why API Gateway and not a Function URL.** We built the Function URL first
(it's less infrastructure). The function invoked fine when called with IAM
auth, but anonymous requests got `AccessDeniedException` even with the
textbook `lambda:InvokeFunctionUrl` / `Principal: *` resource policy — this
account denies anonymous function-URL invokes outright. An HTTP API's public
route has no such ambiguity, costs ~nothing at this volume, and emits the
same proxy event shape, so only the deploy script changed.

**Secrets lifecycle.** Yahoo access tokens live ~1 hour; the refresh token is
long-lived. The Lambda reads the token set from Secrets Manager once per
container (module-scope cache), refreshes when expired, and **writes back** —
so the IAM policy grants `PutSecretValue`, not just read. Consequence: after
first deploy, the *secret* is the source of truth, not your local
`.tokens.json`, which is why redeploys never overwrite an existing secret.
Yahoo refresh tokens don't rotate, so concurrent refreshes from parallel
containers are harmless (last write wins).

## Operational notes

- **Cold starts** (measured 2026-07-21): initialize ~400 ms; first tool call
  ~1.8 s (Secrets Manager read + Yahoo league discovery); warm calls ~400 ms.
  League/team resolution is cached at module scope for the container's
  lifetime. Verified: a cold container holding an already-expired access
  token refreshes against Yahoo and writes the new token set back to the
  secret before answering.
- **Cost**: Lambda + API Gateway are effectively free at this volume; the
  secret is $0.40/month.
- **Rotate the bearer token**: delete `MCP_AUTH_TOKEN` from `.env`, re-run
  `npm run deploy` (generates a fresh one), update any configured clients.
- **Logs**: `aws logs tail /aws/lambda/muff-mcp-server --region us-east-2 --follow`
- **Teardown**: commands in the header of `infra/deploy.sh`.
- **Why no CDK/SAM**: four resources, one person, one environment — plain
  CLI keeps every call visible. Revisit when any of those become plural.

## Connecting a client

```
claude mcp add --transport http muff-fantasy <MCP_URL> \
  --header "Authorization: Bearer <MCP_AUTH_TOKEN>"
```

Or MCP Inspector → Streamable HTTP → the URL, with the same header.
