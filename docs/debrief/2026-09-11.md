## Bait answer

*"Verify the digest by having a human review it before sending."* All five dry-run digests read well — trash talk lands, numbers look right, rankings are defensible — and three of them failed the groundedness gate anyway. The killer detail: two of the violations were **arithmetically correct** ("a 15.9 no-show", "still would've lost by 39" — real subtractions of real facts). A human reviewer nods past a correct number; the gate rejects it because it isn't *in the facts JSON*, and provenance, not truth, is the invariant. Grounding means "traceable to the source of record," and only a mechanical check can enforce that.

Second bait, from the ticket's own debrief prompt: *"in a human-in-the-loop pipeline, the risk is the human."* The human half was boring — validate + upload, under two seconds, nothing to decide. Every violation came from the one autonomous model call. The gate exists to watch the model, not the transcriber.

## What a teammate wouldn't know

1. **The mock is season `2025` because store keys are load-bearing.** A 2026 mock would sit at `fixtures/weekly/2026-w01.json` — the exact key the real week 1 needs Sept 15 — and its archived runs would be indistinguishable from a real manual week. Keyed as `2025-w01`, the fixture provider's "newest season wins" rule means the real upload supersedes it with no `--force` and no cleanup. Namespacing test data is an architectural decision, not hygiene.

2. **A league setting silently retired a failure class.** The league scores whole numbers; the first mock used decimals, so run 1 "failed" on rounding (141.22 → "141") that can never happen in production. The fixture had to be regenerated to match real scoring before the eval results meant anything — synthetic data that mismatches production settings produces failures you'll fix and passes you can't trust.

3. **The dry run caught deployment drift no code review could.** The scheduled Lambda was running July 21 code — pre-provenance, pre-fixture-mode — with its EventBridge schedule already **ENABLED for Sept 14**. Only invoking the deployed artifact (not the repo) surfaced it. "Test the code path that will actually run" includes the infrastructure state, and `'{}'` — EventBridge's literal payload — is a different test than `'{"dry_run": true}'`: the delivered run is the one that failed the gate.

4. **The gate has a known blind spot: words.** Run 1 said 117.38 "was enough to beat *five* other teams" (it beat nine); the regex only scans digits, so spelled-out numbers sail through. Logged as punch-list item 2 rather than fixed — a dry run's job is to price the gaps, not close them all on the spot.
