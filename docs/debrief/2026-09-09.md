## Task statement touched

Human-in-the-loop as *architecture*, not a hack: when the autonomous path (Yahoo API) is blocked, the human becomes a data source with the same contract as the machines.

- `src/mcp/fixture-data.ts` + `src/mcp/data.ts` → HITL as a first-class provider behind the existing seam. `data.ts` types it `typeof yahoo`, so the compiler proves the human-fed path implements the exact API contract; digest, tools and evals stay provider-blind.
- `scripts/fixture-upload.ts` → the deterministic boundary between human input and autonomous pipeline: schema + cross-field validation runs *before* anything touches S3, refuses invalid fixtures and silent overwrites, and stamps `ingested_at`.
- `Provenance` (`provider.ts` → `facts.ts` → `lambda.ts`) → degraded mode is observable: every archived run and `MUFF_RUN` log line says whether the week was API or hand-typed. The model never sees it.
- `infra/deploy-digest.sh` → the mode flip is a deploy-time decision (validated env var), and the Lambda gets read-only, prefix-scoped access to `fixtures/*` — the autonomous side can consume human input but can never write it.

## Bait answer

*"Make manual mode the fallback: if the provider is unset or the API errors, fall through to the fixture path so the digest always ships."*

Today's diff argues the opposite in a comment: "an unknown value still means yahoo, never silently manual." A fallthrough means a typo'd `FANTASY_PROVIDER` — or a transient Yahoo outage — silently swaps the league's digest onto week-old hand-typed numbers with nobody deciding that. Degraded mode is a *decision*, so it's an explicit enum value, validated at deploy time (`deploy-digest.sh` exits on anything but `yahoo|fixture`), and stamped into every run's provenance. Escalation to a human is fine; *silent* escalation is the bug.

Second bait: *"human-in-the-loop means the human approves the agent's output."* HITL here is on the **input** side — the human feeds the pipeline, and everything downstream (facts, one Opus call, render, evals, delivery) stays fully autonomous and unchanged. The exam pattern is "where does the human sit in the loop," not "a human reads the end."

## What a teammate wouldn't know

1. **Provenance had to be stripped in two places, not zero and not one.** It rides on `WeekFacts` for the archive, but `generate.ts` destructures it out of the prompt *and* `eval/checks.ts` excludes it from the grounded-number set — an ISO timestamp is a bag of digits that would silently widen what counts as a "grounded" number, weakening the groundedness gate every week. Metadata on the facts object is never free; every consumer of the object votes on whether it leaks.

2. **There is no "latest" pointer, on purpose.** MUFF-43's open question ("who writes the pointer?") dissolved: zero-padded keys (`fixtures/weekly/2026-w03.json`) make a sorted listing chronological, so the newest key *is* the latest completed week and `current_week = latest + 1` reproduces Yahoo's Tuesday-morning semantics. A pointer is a second write that can race, go stale, or be forgotten; a naming convention can't.

3. **The upload gate cross-checks against last week's fixture from the same store**, so record/points-for deltas are verified automatically on every upload after the first — but only after the first. Week 1 (and any gap) uploads with "deltas not verified," which is exactly when transcription is most error-prone. Hence PR #18: the checklist now carries the exact 14 team strings, emoji included, because the validator can't catch a name that's consistently wrong.

4. **Fixture mode refuses two tools rather than faking them.** `get_roster`/`get_matchup` throw "not available in fixture mode… do not retry; use get_standings or get_week_results" — mapped through the existing errors-are-data contract so the *agent* reads the refusal and reroutes. A degraded provider that stubbed empty rosters would look healthy and answer wrongly.

**Answer to the ticket's debrief question** (*why is `source: "manual"` worth the extra field?*): because without it, degraded-mode weeks are indistinguishable forever. A transcription typo found in week 5 couldn't be traced to which archived digests it poisoned; a manual week could be promoted into `eval/golden/` and pin a human error as ground truth; and when Yahoo access returns, season-level cost/quality comparisons would silently mix hand-typed and API weeks. One enum on the run record makes every one of those a CloudWatch/archive query instead of an unanswerable question.
