# End-to-end dry run — 2026-09-10 (MUFF-59)

One full pass of the degraded-mode pipeline on a mock week: hand-filled fixture →
validate → upload → `FANTASY_PROVIDER=fixture` digest → eval gate → Telegram (self).
Everything below is what actually happened, including the two things the gate caught.

## The fixture

`fixtures/weekly/2025-w01.dryrun.json` — the real 14-team 2026 league (team strings
and manager first names from `docs/ingestion-checklist.md`), invented but
internally consistent numbers: one blowout (53), one nail-biter (1), a
start/sit blunder that would have flipped a result, four transactions, bench
totals for all fourteen teams. Scores are **whole numbers** — the league scores
without decimals — while projections keep Yahoo's decimals. (The first two runs
below used a decimal-scored version of the same fixture; the third is the
whole-number one that stays in the repo.)

Why season `2025`: the store key is a pure function of (season, week), so a
`2026` mock would sit at `fixtures/weekly/2026-w01.json` — the exact key the real
week 1 needs on Sept 15 — and its archived run would be indistinguishable from a
real manual week. As `2025-w01` it never collides, and because the fixture
provider serves the newest season present, uploading the real 2026 week 1
supersedes it with no `--force` and no cleanup. The league name says
"(dry-run mock)" and `source.notes` says do not promote to golden.

## Groundedness: 5 runs, 3 violations, all caught

Read as a league member the digest is good — the trash talk lands, the numbers
are the numbers, the power rankings are defensible. The eval gate still failed
both runs, and it was right both times:

1. **Run 1, headline: "Phi Drops 141"** — 141.22 rounded to a whole number. The
   prompt allows one decimal; the checker allows one decimal; the model went to
   zero. Small, but exactly the class of drift the gate exists for. **Moot for
   the real league**: scoring has no decimals, so there is nothing to round —
   run 3 on whole-number scores produced the same headline and passed.
2. **Run 2, trash talk + rankings: "a 15.9 no-show"** — Leapfrog Clause was
   projected 111.62 and scored 95.70. The delta (15.92) is *correct* but it is
   not in the facts: `facts.ts` only publishes the single best and worst
   projection miss. The model did arithmetic, which the design forbids
   regardless of whether it got the sum right.
3. **Lambda delivered run, trash talk: "a game he still would've lost by 39"**
   — 53 (the margin) minus 14 (the start/sit delta). Whole-number scoring, so
   no rounding possible; this is pure model arithmetic again, on the exact
   EventBridge code path. Same class as #2, and the one the league would
   actually have received.

Both are the digest's fault, not the fixture's, and neither would have been
spotted by a human skim. Two of the five runs passed clean. The three failures are one rounding (moot on
whole-number scoring) and two subtractions — the model doing arithmetic the
design reserves for `facts.ts`. That is the Day 4 prompt fix, and it is the
only punch-list item that changes what the league reads. That is the groundedness story: the rule layer catches
what a reader nods past.

boring in the best way — validate, upload, done in under two seconds with
nothing to decide. The surprise was on the autonomous side: the flagship
invariant ("every number is computed in code") held in the pipeline and was
